Two export reports arrive for the same fictional week. One says route A performs better in both document groups. The other gives route B the higher overall success proportion. Before accusing the spreadsheet of having a personality, check what each percentage counts.

## Read the counted unit

One record is **one document, one completed export attempt and one binary outcome**: it passed the stipulated validation checks before the deadline, or it did not. Routine and complex are classifications known before route choice. They are disjoint and exhaustive: every attempt belongs to exactly one group. The table contains every attempt in this constructed week. Route allocation is not stated to be random.

A **proportion** is an event count divided by its eligible total. A **stratum** is one of the named groups used to partition the records. An **aggregate** combines those groups. None of these words supplies a reason that a route caused the outcomes.

## Keep both reports in view

In routine work, A has $9/10=90\%$, while B has $72/90=80\%$. In complex work, A has $36/90=40\%$, while B has $3/10=30\%$. A is ten **percentage points** higher in each group: subtraction on the percentage scale. That is not a claim of ten per cent relative improvement.

The overall calculations instead use A's $(9+36)/(10+90)=45/100$ and B's $(72+3)/(90+10)=75/100$. A handled mostly complex work; B handled mostly routine work. These unequal mixtures accompany a strict reversal of the within-group ranking, called **Simpson’s paradox** here. The arithmetic is compatible because the denominators answer different questions.

Think of combining trays of different sizes: each document gets counted once, rather than each tray receiving one equal vote. The analogy works only if the trays do not overlap and the same outcome is counted throughout. We will work that accounting explicitly in the next lesson.

### When this question matters

Use this audit when a dashboard combines groups or when a ranking changes after a report is split. The first task is to identify the compared populations, not to declare that the aggregate or the subgroup table must always be the correct answer.

The learning path builds one procedure across six teaching lessons:

1. **[Build the total from its denominators](/simpsons-paradox-and-aggregation/01-build-the-weighted-total)** derives the weighted identity and checks the equal-group trap.

4. **[Check what the table cannot identify](/simpsons-paradox-and-aggregation/04-what-the-table-cannot-identify)** constructs compatible causal completions and a selected subset.
