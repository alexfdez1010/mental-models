A proposed redesign has a familiar pitch: “The current design is a local peak. Accept a temporary setback and we can reach something better.” The first sentence does not establish the second. You still need a permitted route, enough steps to finish it and intermediate states you can tolerate.

We will audit that proposal on a complete, deliberately small map. The point is to check a recommendation rather than decorate it with a mountain.

## Write the decision card

A fictional test rig has four configurations. Its performance rubric assigns the fixed scores below, in points; higher is better. The table gives **every** state and **every** permitted neighbouring change. A neighbour is a state joined by one declared link. No noise, hidden states or changing environment are included.

A link permits one change. It does not introduce all the intermediate positions on the drawn line as extra states. You may also **hold** at your current state. Holding is a separate action, not a claim that a state is its own neighbour.

Here is the planning task we will compare with hill-climbing:

| Item | Declared rule |
| --- | --- |
| Start | S |
| Time available | Three decision slots; each permits one adjacent move or a hold |
| Minimum | Every visited score, including the starting score, must be at least 5 points |
| Objective | Maximise the score at the final slot |
| Information | The auditor knows the entire map; the local rule will use only current/neighbour scores |
| Omitted quantities | No movement or setup costs, intermediate rewards, random outcomes or discovery benefits |

A **decision slot** is one opportunity to act; it is not a measured day or generation. A **minimum** is a condition that must hold along the whole path. The **terminal objective** judges only the final state. This resembles a route with a minimum service level at every stop, but there is no real transport, production or safety claim behind these points. Adding a rebuilding cost or uncertain score would change the problem.

### When to use the card

Write these items before recommending a worse-first change. If two people disagree about the recommendation, they may be maximising different quantities or allowing different moves. A higher endpoint alone does not settle either issue.

## Run the rule that was actually specified

First use **strict steepest ascent**: inspect every immediate neighbour; move to a highest-scoring neighbour only if it strictly improves the current score; otherwise stop. “Strict” rules out an equal-score move as well as a worse one. All scores on this map are distinct, so no tie-break is needed.

From S, the only neighbour is A. Its score is 5, below S's 6, so the strict rule stops at S. Giving the operator a picture of C does not change that acceptance rule. Knowledge and permission are separate: this rule refuses the first move even if an auditor knows where it leads.

From A, compare both neighbours: S scores 6 and B scores 8. The rule takes B, the better neighbour, rather than accepting just any improvement. At B, A scores 5 and C scores 9, so it takes C. At C its only neighbour B is lower, so it stops. These are all four starting cases:

A **local optimum** has no permitted neighbour with a higher score. A **global optimum** has a highest score across the entire declared map. S is locally optimal but not globally optimal; C is both. We can certify C as global because all four states and scores are known. Merely observing a stopped search would establish less.

The **basin** of an endpoint is the set of declared starts whose traces end there under this particular rule. S's basin contains one start; C's contains three.

Those are $1/4=25\%$ and $3/4=75\%$ of a catalogue, a gap of 50 percentage points. They are not probabilities for a restart procedure: we have not supplied a law for choosing the initial state. Nor do they compare the constrained planning task yet.

Each accepted strict move raises the score. On a finite map with $N$ states, a strict trace cannot return to a previous state: doing so would require the same state's fixed score to be higher than itself. It therefore accepts at most $N-1$ moves before stopping. This proves termination in a finite model, not global optimality, a runtime bound in seconds or a theorem about biological evolution.

## Audit the deadline

### When the horizon changes

A longer horizon changes which endpoints can be reached. It does not change the four scores or add a direct edge to C. For this map and minimum, the best terminal scores at zero, one, two and three slots are 6, 6, 8 and 9. A fixed number of steps is part of the result, not an inconvenient footnote.

## Check the minimum at every visited state

Keep the same map and start, but raise the minimum to 6. The initial S still qualifies. The first move to A does not: its score is 5. Since every route leaving S starts with A, the only feasible plan is to hold at S throughout.

This is the difference between **feasible** and **attractive at the endpoint**. A feasible path meets every declared constraint. Ending at 9 does not repair an earlier violation. Of the thirteen three-slot graph paths, all thirteen meet minimum 5, while only S→S→S→S meets minimum 6.

### When a worse-first plan is acceptable

Check the low point as well as the endpoint. In this model a one-point loss is acceptable under minimum 5 and forbidden under minimum 6. The size of a later gain does not silently relax the constraint. In a real proposal, you would need evidence for the score estimates and a defensible meaning for that minimum before using this calculation.

## Use the audit with its boundary

The complete map made this proof possible. In a larger problem, a stopped local search does not reveal all unvisited states, and an attractive sketch is not a complete catalogue. Uncertain scores, changing neighbours, setup losses or cumulative rewards require a revised model. None is represented by silently reinterpreting a point score as profit, probability or biological reproductive success.

Exploring unknown alternatives is also a different task from planning on this fully known map. Here there is no information to buy, and no theorem requires a positive exploration share. Under the stricter minimum, holding is optimal for the stated objective and horizon. With missing information, investigation may have value, but that requires specifying what can be learned and what the investigation costs.

The [Berkeley local-search notes](https://inst.eecs.berkeley.edu/~cs188/textbook/csp/local-search.html) distinguish hill-climbing from a method that can accept worsening moves. [Poole and Mackworth's local-search chapter](https://www.cs.ubc.ca/~poole/aibook/3e/html/ArtInt3e.Ch4.S6.html) defines optimality relative to possible successors and distinguishes search variants. Our strict rule and finite counts are stipulated and derived here; they are not measured performance claims from either text.
