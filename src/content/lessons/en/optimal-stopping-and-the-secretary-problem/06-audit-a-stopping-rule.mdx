A stopping rule is a set of instructions for deciding when to stop from the information available **at that moment**. A completed record is much more generous: it tells you what came next. Confusing those two views lets hindsight do the difficult part and then invoice the rule for genius.

The earlier lessons introduced sampling, records and alternative objectives. Here you will audit a complete protocol, distinguish a correctly executed loss from a mistake, and compare the same policy under two fully specified order laws. Every numerical case below is constructed. These are exact calculations inside declared models, not measured success rates from a hiring market.

## Write down what the chooser may know

Imagine a referee holding the complete result sheet while a player sees only the current move. The referee can later assess a decision; the player cannot borrow the sheet during play. The analogy has a limit: known rules of the game are legitimate information. A chooser may infer something about the future from a supplied model without observing the future itself.

A stopping rule is **admissible for an information model** if it uses only information that model allows. The key restriction is about when information becomes available, not whether a completed trace looks sensible. Ferguson's definition of stopping rules makes this distinction explicit: the decision can depend on the observed history, rather than on later observations. [Author's treatment of stopping rules](https://www.math.ucla.edu/~tom/Stopping/sr1.pdf)

Our game offers six display designs, one at a time. Their quality has a fixed strict ordering; comparison is perfect. The chooser sees which revealed designs beat which others, but receives no absolute score and cannot identify an unseen design's global rank.

| Protocol item | Declared condition |
| --- | --- |
| Horizon | Exactly six designs, known before the run |
| Objective | Select the unique greatest; reward one for success and zero otherwise |
| Observation | Relative ordering of revealed designs only |
| Action | Accept the current design and finish, or reject it permanently |
| Availability | Every current design can be accepted; no recall of rejected ones |
| Other features | No ties, inspection costs, rank errors or refusal by the selected option |
| Reference order law | All permutations are equally likely, fixed before the rule is chosen |
| End condition | Select the final design if the policy has not already selected one |

**Worked information check.** After two observations, the second design beats the first. The chooser knows their relative ordering and arrival positions. The chooser does not know whether the second is second-best or greatest globally. A completed record labelled $(2,5,1,4,6,3)$ and another labelled $(4,6,1,3,2,5)$ produce the same comparisons during those first two observations. A rule using only that history must make the same decision in both.

The completed-record labels run from one to six, with six greatest. They are **analyst notation**, not values disclosed to the chooser. A rule saying “accept when global label six appears” would solve a different, more informative game.

### When to use this check

Use it before judging an algorithm from a worked trace, replay or dashboard. Hide future values and global ranks, then ask whether each decision can still be reconstructed. If it cannot, the trace has smuggled in information.

## Execute a rule that actually stops

A **record** is an arriving option better than every option previously observed. Think of a high-jump bar set by the opening observations: the rule reacts when a later design clears it. The bar compares order, not quality gaps; it does not tell you how much better one design is.

Choose an integer $k$, the number of opening rejections, **before any option is revealed**. We will compare $k=0,1,2,3,4,5$.

1. Reject the first $k$ designs and remember their best.
2. Thereafter, select the first new record and end the run immediately.
3. If no eligible record appears, select the final design anyway.
4. With $k=0$, select the first design. There is no opening sample.

The fallback is part of the rule, not a last-minute repair. Without it, “reject everything if the best was in the sample” is an incomplete description of this one-selection game.

In the visual, choose a teaching run and cutoff before revealing anything. Each click executes the rule; it does not invite a hindsight override. The bars show **relative ordering among the designs revealed now**. Their changing heights encode ordinal comparisons, not absolute quality differences. Only the explicit completed-record debrief displays global labels and the unseen remainder. These are replayable teaching records, not blinded trials.

### When the rule is complete enough to test

Another person should be able to run it on every permitted order without asking what to do at a boundary. Specify the zero-sample case, the final option and whether equality is possible. Here ties are excluded; a real ranking system with ties would need a further rule.

## Separate correct execution from a winning outcome

The distinction resembles a correctly executed move in a game with an uncertain opponent: following the plan is not a certificate of winning. Our game has no opponent making decisions; uncertainty comes from the order drawn under its declared law.

Now switch explicitly to the **analyst's completed-record view**. The labels below reveal the whole ordering after the decision. They must not be read back into the chooser's earlier information.

| Run | Complete analyst record | Selection with $k=2$ | Result |
| --- | --- | --- | --- |
| A | 2, 5, 1, 4, 6, 3 | Position 5, global rank 6 | Success |
| B | 2, 4, 5, 1, 6, 3 | Position 3, global rank 5 | Loss |
| C | 6, 1, 2, 3, 4, 5 | Position 6, global rank 5 | Loss by final fallback |

**Worked loss.** In B, the opening leader has analyst label four. The third option, label five, beats it and is therefore selected. The greatest, label six, appears later at position five. Rejecting the third option *because of that later arrival* would violate the information restriction. Waiting might happen to win this completed record; it is not the declared first-record policy.

In C, the greatest was rejected during sampling. Nothing later can beat it. The rule still makes a selection at the end: position six. This is a correctly executed fallback with a losing outcome. Changing $k$ only after inspecting such records would create a retrospective recommendation, not an advance policy test.

### When a replay helps

Use individual replays to find implementation errors and understand mechanisms. To compare success probabilities, you need the full probability model or a justified sampling procedure. Runs A, B and C were chosen for teaching; their success fraction is not an estimate of the uniform-order policy's performance.

With six distinct designs there are $6!=720$ possible arrival orders. In the reference model **each has probability $1/720$**. Execute the same cutoff on every order, count selections of the greatest, and divide by $720$. This is exhaustive model calculation, not a survey of visitors or repeated empirical trials.

| Opening rejections $k$ | Winning orders | All permitted orders | Success probability |
| --- | --- | --- | --- |
| 0 | 120 | 720 | 16.67% |
| 1 | 274 | 720 | 38.06% |
| 2 | 308 | 720 | 42.78% |
| 3 | 282 | 720 | 39.17% |
| 4 | 216 | 720 | 30.00% |
| 5 | 120 | 720 | 16.67% |

The best **among these six cutoff policies** rejects two. Its exact success probability is $308/720=77/180$. The percentage is rounded in the table. Its sampling fraction is $2/6\approx33.33\%$, while its success rate is approximately $42.78\%$: they have different denominators and are not the same quantity.

### Check the count by a different route

Let the greatest arrive at position $m$, after the opening sample. Its position has probability $1/6$. For the rule to reach it without an earlier selection, the best among the preceding $m-1$ designs must lie in the first $k$. Under uniform ordering that conditional probability is $k/(m-1)$. Sum over the possible positions:

$$
P_k=\sum_{m=k+1}^{6}\frac{1}{6}\frac{k}{m-1}
=\frac{k}{6}\sum_{j=k}^{5}\frac{1}{j},\qquad 1\le k\le5.
$$

For $k=2$:

$$
P_2=\frac{2}{6}\left(\frac12+\frac13+\frac14+\frac15\right)
=\frac{77}{180}=\frac{308}{720}.
$$

The factor $k/6$ in the rearranged expression is **not** the chance the greatest comes after the sample; that chance is $(6-k)/6$. Keep the conditional argument intact instead of assigning a separate probability story to each algebraic factor. For $k=0$, the rule selects the first, giving probability $1/6$.

Ferguson's classical treatment derives the threshold family and its finite success formula under the stated rank-only, uniform-order assumptions. Its first eligible stage is one larger than our opening rejection count. The large-pool result concerns a limit toward $1/e$; it is not an instruction to force the finite sampling fraction and success probability to equal that number. [Classical derivation and finite table](https://www.math.ucla.edu/~tom/Stopping/sr2.pdf)

## Test a changed law without changing the objective

Here is your independent transfer problem. Keep the horizon, reward, relative observations, availability and no-recall rule. Change **only the known law of complete orders**. Before choosing the cutoff, the chooser is told that exactly these four orders are possible, each with probability $1/4$, and therefore that the greatest always arrives last. The chooser is not told which row will occur or shown the unseen global labels during play.

| Permitted order | Complete analyst labels | Model probability |
| --- | --- | --- |
| A | 5, 1, 2, 3, 4, 6 | 1/4 |
| B | 1, 2, 3, 4, 5, 6 | 1/4 |
| C | 2, 1, 4, 3, 5, 6 | 1/4 |
| D | 1, 3, 2, 5, 4, 6 | 1/4 |

This is the entire stipulated probability space, **not four observations sampled from the old set of 720**. Think of changing the deck-building rule before shuffling, rather than drawing four cards and declaring the rest impossible. The analogy stops at that distinction: our outcomes are complete arrival orders, not individual cards.

Without opening the solution, trace the reject-two policy on every row. Then compare all six cutoffs and choose one under this changed law. State exactly which advance information justifies your choice.

Rejecting five selects the final option and wins $4/4=100\%$. It uses the known last-greatest guarantee, without requiring unseen comparisons. Since no success probability can exceed one, this also reaches an upper bound under this changed model. It is not a reason to wait until the last option in the original uniform-order game, where that policy wins only $120/720=1/6$.

### When to challenge the law rather than tweak the cutoff

If options are scheduled, filtered or sorted, inspect the arrival process before importing a uniform-order probability. Re-estimating a cutoff cannot repair a false claim that every permutation is equally likely. Conversely, an unverified belief that the best arrives late is not permission to treat it as a guarantee.

## Finish the audit before exporting the rule

An audit resembles checking a route before using travel directions: the instructions may be internally consistent while a closed bridge makes the route unsuitable. The limit is that uncertain arrival laws may never be verified exactly. The practical task is to state what supports the model and what would make you revise it.

| Audit question | Concrete check | If it fails |
| --- | --- | --- |
| What is rewarded? | Unique-greatest indicator, mean rank, numeric value or another specified payoff? | Recompute for the actual objective; the metrics are not interchangeable |
| What can be known now? | Reproduce the decision using revealed comparisons and declared prior information | Remove hindsight or solve the more informative problem explicitly |
| Does the rule cover every path? | Check opening cutoff, first eligible record and final fallback | Complete the protocol before scoring it |
| Which orders and probabilities apply? | List the finite model or justify an arrival process | Qualify the success claim; do not invent a uniform law |
| What would invalidate the deployment? | Changed scheduling, availability, ties, costs or measurement errors | Revisit the model and re-evaluate, rather than promise the old percentage |

**Worked transfer to planning.** A display coordinator can retain all six proposals and compare them after the deadline at no cost, with every proposal still available. The original no-recall game no longer describes the process. Comparing all six and choosing the greatest guarantees success *under those new stated conditions*. If proposals can expire or comparison takes time, that argument needs revision too. The word “sequential” alone does not determine the optimal stopping policy.
