Two rules give exactly the same outputs in a table. One is short; the other adds a term. Have you discovered which is true, or only which you would prefer to investigate first?

**Occam's razor** is a preference against unnecessary commitments among explanations adequate for the same job. A commitment is something a model asserts or needs to assume. *Unnecessary* requires a comparison: what are we explaining, with which data, under which conditions? Counting lines does not answer those questions.

## What can be trimmed

Think of a suitcase packed for a particular trip. Removing a spare cover you will never use lightens it; removing the coat you need does not improve the packing. The comparison requires a destination. The analogy has a limit: weight is directly measurable, while explanatory complexity depends on representation and the job an explanation must do.

An **assumption** is a condition we accept for reasoning that the case's data have not established. An **observation** is a recorded result. A **hypothesis** is a claim we want to evaluate. “The log records a deployment” and “that deployment caused the failure” are different claims: the first can be an observation; the second needs testing.

| Comparison | Useful question | Shortcut that fails |
|---|---|---|
| Two descriptions of the same rule | Does an abbreviation change its commitments? | Counting words as probabilities |
| Two rules with equal initial fit | Where do their predictions differ? | Declaring the shorter rule true |
| A proposed cause and a recorded fact | What mechanism and test connect them? | Calling an earlier event the cause |

### When to use this criterion

Use it to notice additions that supply neither explanatory work nor a useful prediction. Keep conditions needed for the purpose: a street map can omit elevation when locating an address; that omission may matter when choosing a cycling route. One level of detail does not suit every job.

## Same fit, different predictions

**Fixed-rule card.** This is a constructed, exact case with no measurement noise. Input $x$ and output $y$ are dimensionless numbers. Fix these two rules before consulting the records:

$$L(x)=2x+1$$
$$C(x)=2x+1+x(x-1)(x-2)$$

We are not estimating coefficients. Every constant is already supplied. For this comparison, C is more elaborate because it adds a term and contains a cubic power when expanded; L is linear. That is an explicit criterion for these representations, not a universal probability formula.

| Input | Initial record | L predicts | Additional term in C | C predicts |
|---:|---:|---:|---:|---:|
| 0 | 1 | 1 | $0(-1)(-2)=0$ | 1 |
| 1 | 3 | 3 | $1(0)(-1)=0$ | 3 |
| 2 | 5 | 5 | $2(1)(0)=0$ | 5 |

The added term vanishes at all three inputs. Both rules match **3 out of 3 records**. Writing C in expanded form or giving it an abbreviation changes none of its predictions.

### When to ask for another record

When existing records do not distinguish candidates, seek an input where they differ. Repeating only the same inputs can check record stability but cannot separate these two deterministic rules.

## A record that can change the preference

Before revealing another result, calculate each rule's prediction. At the first new input, C adds $3\times2\times1=6$ to L's output. At the next it adds $4\times3\times2=24$.

| New input | L predicts | C predicts |
|---:|---:|---:|
| 3 | 7 | 13 |
| 4 | 9 | 33 |

Consider two separately constructed confirmation batches: batch **L** records 7 and 9; batch **C** records 13 and 33. One batch is not an observed continuation of the other. Select each scenario and compare matches.

### When to use confirmation

Separate records used to propose a rule from records used to check its predictions. NIST recommends collecting confirmation data and warns that a good local fit does not guarantee predictions beyond the observed domain. This card illustrates the issue; it does not establish an optimal model-selection procedure.

## A record does not contain the whole cause

**Outage card, also constructed.** Trust the records' authenticity and clocks. A deployment occurred at 02:55; the first symptom *observed so far* was recorded at 03:00. Investigating the new version is reasonable. Those timestamps do not establish that it caused the outage.

| Additional information | What changes | What it does not establish |
|---|---|---|
| Intrusion recorded at 02:30 | Refutes “no intrusion occurred” | Does not exclude the deployment contributing too |
| Earlier failure recorded at 02:40 | Refutes “the 02:55 deployment initiated that earlier failure” | Does not exclude the deployment worsening that failure later |
| In reset copies with the same data and configuration, the new version fails and the old version does not | Distinguishes those versions under the setup's controls | Does not itself reproduce every production condition |

We have assigned no probabilities to these causes. Nor have we stipulated mutual exclusivity. An intrusion and a version defect can coexist or interact. To reject a claim, name the precise claim that the record contradicts.

### When to make this separation

Before changing explanations because of a new headline, write down what was recorded, what you inferred and which prediction changes. You can revise a hypothesis without prematurely declaring its rival true.

## Probability and the next check

A **prior**, in a probability model, is a probability distribution before incorporating the data under analysis. It does not mean “the best explanation because it is short.” Calculating posterior probabilities requires prior probabilities and a model of how each hypothesis produces data. They do not come from counting lines.

MacKay's Bayesian treatment compares predictive distributions and specified probabilities, including parameter distributions where there are parameters. Our example uses two fixed rules: we have calculated neither an Occam factor nor their posterior probabilities.

A useful routine: state the purpose, separate observations from assumptions, compare predictions and seek a check that could change the preference. The costs of error and testing also matter when deciding what to investigate first. Being easiest to test does not make a hypothesis most likely true.

**Transfer card.** This independent case is also exact and noiseless, with dimensionless input and output. The fixed rules are:

$$U(x)=3x+2,\qquad V(x)=3x+2+2x(x-1)(x-2)$$

Initial records are $(0,2),(1,5),(2,8)$. First calculate V at the new input $x=3$, then open the working.
